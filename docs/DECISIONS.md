# 주요 설계 결정

현재 구현에 반영된 결정이다. 새로운 결정은 이유·유지 조건·영향받는 코드/검사를 함께 기록한다. 오래된 선택을 조용히 삭제하기보다 변경 이유와 날짜를 남긴다.

## FreeMind 호환의 기준

FreeMind 1.0.1의 일상 편집과 `.mm` 의미 보존을 기준으로 한다. Java/Swing UI를 직접 포팅하지 않고 React로 재구현한다. 알 수 없는 XML을 소속 노드와 함께 보존하며 암호화와 안전하게 해석할 수 없는 파일은 거절한다. 자유 좌표는 WebMind 확장으로 왕복하지만 FreeMind의 픽셀 배치와 같다고 보장하지 않는다. GPL-2.0-or-later를 사용하고 재사용 출처는 [THIRD_PARTY_NOTICES](../THIRD_PARTY_NOTICES.md)에 관리한다.

## 편집과 렌더링 분리

트리·이동·레이아웃·변환은 `shared/`, UI는 `src/`로 분리한다. SVG 연결선과 HTML 노드를 사용해 리치 콘텐츠·텍스트 입력·터치 조작을 지원한다. 노드 ID를 안정적으로 유지하며 이동·삭제·붙여넣기는 트리와 화살표를 함께 검증한다. 한글 IME, 브라우저 예약 단축키 대체, 모바일 메뉴 조작은 기능 계약이다.

## 단일 서버와 SQLite

소수 사용자의 비용과 운영 복잡도를 줄이기 위해 단일 Fastify 프로세스와 로컬 디스크 SQLite WAL을 사용한다. 현재 공유 Lightsail의 기존 Nginx 뒤에서 전용 사용자·systemd·loopback 포트로 격리한다. Docker는 별도 배포 선택지이며 현재 운영 경로가 아니다. 여러 프로세스/서버의 수평 확장은 현재 저장 직렬화·세션·rate limit 설계의 범위를 벗어난다. [SERVER](SERVER.md), [DEPLOYMENT](DEPLOYMENT.md).

## 서버 본문 저장에서 사용자 Drive로 전환

2026-10-01 구현: `local | drive | legacy`를 구분하고 신규 본문과 이미지는 브라우저 또는 사용자 Drive를 원본으로 삼는다. 서버는 회원·암호화 토큰·목록 캐시·작업 기록을 보관한다. 이전 서버 데이터는 검증 후 Drive에 복사하고 원본은 읽기 전용으로 남긴다. 캐시와 중복 방지/이전 기록은 성격이 다르므로 함께 삭제하지 않는다. 서버 DB 백업은 Drive 본문 백업을 대체하지 않는다.

## 로그인과 Drive 동의 분리

이메일 로그인과 Google 로그인을 유지하고, Drive는 별도 동의에서 `drive.file` 최소 범위를 요청한다. 앱 생성 파일과 Picker로 직접 선택한 파일만 취급한다. 폴더 선택이 모든 내부 파일 접근을 보장하지 않는다. 사용자당 Google 계정 하나·개인 Drive 본인 소유 파일을 지원한다. 이메일 일치만으로 자동 계정 연결하지 않고 로그인한 사용자가 명시적으로 연결한다. 토큰 암호화에 쓰는 AUTH_SECRET은 안정적으로 보관한다.

## 원본 보호와 충돌

사전 버전 확인 뒤 업로드하기만 하면 그 사이 외부 수정이 유실될 수 있다. 실제 오래된 조건부 요청이 거절되는 것을 확인한 연결·파일에서만 원본 갱신한다. 검증되지 않았거나 ETag가 없으면 별도 변경본을 저장한다. 이 정책은 OAuth 공개 요구사항이 아니다. 2026-10-04 실제 연결은 조건부 검증 false/ETag 없음으로 보호 모드를 유지했다. 파일 증가 UX를 개선하더라도 플래그만 켜거나 충돌 검사를 제거하지 않는다.

## 거짓 충돌과 초안 복구 수정

2026-10-04, 제품 커밋 `42a8167`: Drive `version`은 보이지 않는 메타데이터 변경에도 증가하므로 본문 체크섬·이름·종류·부모로 편집 리비전을 판단한다. 읽는 동안 실제 본문이 바뀐 경우는 여전히 거절한다. 리비전 판단과 원자적 업로드 보장은 별개다.

저장 이전의 늦은 GET, 초기 dirty 초안 인식 지연, 저장 응답/IndexedDB 대기 중 입력 덮어쓰기를 함께 수정했다. 화면 최신 입력과 원격 응답의 메타데이터를 분리해 반영하고, 복구 초안은 첫 렌더부터 dirty로 취급한다. 최신본을 열기 전에 현재 작업을 독립적인 로컬 문서로 보관한다. 관련 불변 조건은 [ARCHITECTURE](ARCHITECTURE.md), 사고 재현/대응은 [TROUBLESHOOTING](TROUBLESHOOTING.md)을 따른다.

## 보존을 우선하는 삭제와 재시도

Drive 삭제는 휴지통 이동이고 앱이 관리하는 해당 문서 첨부만 함께 처리한다. 외부 원본 이미지는 지우지 않는다. 로컬 이미지도 다른 탭의 초안·undo가 참조할 수 있어 문서 삭제만으로 일괄 제거하지 않는다. 자동 병합은 하지 않으며 불확실한 저장은 같은 requestId/snapshot을 재사용한다. 현재 pending 요청은 메모리 상태이므로 새로고침을 포함한 완전한 exactly-once 저장은 보장하지 않는다.
